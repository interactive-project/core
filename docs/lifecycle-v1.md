# Headless lifecycle and deterministic dispatch v1

createRuntime coordinates a synchronous portable-state engine. It returns the Protocol EngineSession dispatch/evaluate/serialize/restore/dispose shape plus start/pause/resume/complete/fail, getState, state/event subscriptions and explicit event flushing. This phase implements synchronous lifecycle/dispatch/evaluation. serialize/restore reject with runtime.snapshotUnavailable until core#4; async reducer/evaluation returns reject with runtime.async until core#3. It does not imply resumable or asynchronous-effect support.

## Legal state graph and errors

Creation validates already supplied ActivitySpec, initial state and a created event before returning lifecycle created. start is legal only from created and commits active. pause is active → paused; resume is paused → active. Domain dispatch requires active. evaluate reads active or paused state without changing it. complete requires active and a matching current-revision completed/unevaluable result; it commits completed. Pending results remain active and complete rejects runtime.pending. Failed evaluation results commit failed with a safe failure event. Explicit fail is legal from created/active/paused and commits failed. Disposing from any state commits disposed and releases subscriptions/outbox/bus/live engine cleanup; repeated disposal is a no-op.

completed/failed are terminal until disposal: no new domain actions or lifecycle restart. Structured RuntimeError carries static safe message, code and pointer for invalid lifecycle, busy/disposed/cancelled operation, unsupported async/snapshot support, invalid JSON/activity/result/event or invalid injected source. Dispatch rejects using Protocol action.disposed/busy/invalid/identity/stale as appropriate. Invalid JSON without an authenticated action UUID uses the documented reserved fallback action ID 00000000-0000-4000-8000-000000000000 solely for diagnostics, never as an accepted action identity. No native exception text is forwarded by the validation/event observer boundary.

This initial runtime accepts a synchronous StatePorts implementation: initialState, pure reduce returning accepted/candidate state or rejected, evaluate returning a Protocol Result, and optional dispose. Reducer exceptions propagate only as live host implementation errors; callers must treat these as failed uncommitted work and never expose native messages to users/telemetry. Later core#3 supplies correlated asynchronous effects/failure orchestration.

## Atomic state and observers

The host observes a deeply frozen view: lifecycle, domain revision, JSON state and optional result. Initial/candidate state and inputs are isolated bounded JSON copies. A reducer sees an immutable prior state/action and produces a candidate; validation/cancellation runs before replacement. Illegal, rejected, cancelled, non-JSON or throwing candidates do not replace state or consume the action sequence. The accepted candidate commits once, increments domain revision and then notifies surviving state observers in registration order. Lifecycle-only transitions do not change domain revision; result.revision must match that domain state. State observers have future-only registration, idempotent unsubscribe, 128-observer ceiling, and isolated throws/rejected promises. No mutable engine handle/state leaks into callbacks.

Action identity matches activity/session/attempt and exact Protocol version. Accepted actions consume contiguous source sequence from zero; rejected actions do not. During transitions/notifications a reentrant dispatch returns action.busy rather than recursively committing state. Control-operation reentrancy throws runtime.busy. Disposal requested during an operation is deferred to its finally boundary, preventing callback disposal from overwriting an in-flight candidate or interrupting a notification transaction. If requested before candidate commit, commit rejects and final cleanup proceeds.

Notifications follow commit; observer failure cannot revert completion or affect other observers. State callback completion precedes event delivery. Created is emitted during construction and is available through explicit retained-tail event replay. Started follows its commit; accepted actions emit interacted with the current action/revision; host pause/resume controls emit interacted using injected UUID control-action IDs and reserved interactive-project/pause/resume names. They are lifecycle controls, not a request to an execution engine. Complete emits a validated matching completed/unevaluable result; fail emits a safe code/phase.

Core prevalidates each event and preflights local bus count/bytes before committing. A bounded in-memory outbox retains an occurrence until admission succeeds; unexpected admission failure never rolls back committed state. Subsequent transitions stop with runtime.eventsBlocked while it is retained. flushEvents retries the exact occurrence, preserving ID, timestamp and source sequence. This heap outbox is not durable remote delivery or a process-crash transaction log. Event subscriptions/replay, FIFO observer failure isolation and finite deduplication use Events' verified bus. Consent/redaction/remote sinks remain events#3.

## Injected environment and adapters

clock supplies nonnegative safe-integer epoch milliseconds; random supplies finite values in [0,1); nextEventId supplies unique UUIDs for events/control actions; identity/source and live services are host-owned. No implicit Date.now, Math.random, global execution provider, fetch, DOM or styling import exists. Services are a shallow readonly live mapping, never portable state. Reducers must remain pure: external work belongs in host-owned effects (core#3). Replaying the same authored data, action trace and injected source values produces the same state and notifications; external service behavior must be recorded in later effect replay.

stateMachinePorts wraps a pure initial/transition/evaluate facade behind the same StatePorts and Protocol session contract. It supports state-machine libraries without importing them into Core. An optional XState adapter supplies a trusted transition facade and explicit portable projection/restoration; native actors, machine closures and vendor snapshots cannot be stored as public JSON. The current custom-machine fixture certifies the adapter boundary, not a particular XState version/package integration. Actual optional XState compatibility belongs to core#5's release harness.

## Verification and scope

Tests run a quiz reducer and minimal custom machine through identical create/start/dispatch/pause/evaluate/resume/complete/dispose traces; repeated cleanup/cancellation are included. Tests verify frozen state, illegal/disposed/stale actions, post-commit observer failure, reentrant action rejection, cancelled/non-JSON candidates, pending/identity-invalid results, unsupported async work and caller-owned cleanup. A registered fixture engine is resolved through Registry and satisfies Protocol EngineSession types. Types compile with ES2022 only. The fixture domain is 0.0.1; actual quiz schemas/engines/UI libraries remain their implementation issues.

Initial JSON budgets are 2 MiB, depth 32, collections 2,000, strings 100,000 and 50,000 values; actions/events use tighter Events limits. Values are never truncated. Live validators are trusted, synchronous and side-effect-free. Load-stage schema/semantic/permission/capability checks, timeout/partial load cleanup and renderer resolution are core#2; async effects core#3; digest/version-bound transactional snapshots core#4.

Existing Protocol/Events wire schemas remain unchanged. Core 0.1.0 is repository implementation, not an asserted npm publication. No prior Core serialized format requires migration. Decision: improvement-proposals/decisions/core-lifecycle-v1.md.
