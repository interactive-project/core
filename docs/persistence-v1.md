# Portable snapshots and restore v1

Use createPersistentRuntime from ./persistence to bind the validated activity to its computed protocol-json-v1 SHA-256 digest. Inject Web Crypto on hosts without it. The root createRuntime also accepts a persistence configuration with an already verified contentDigest; the host must compute that value from the exact activity rather than trusting a snapshot.

serialize uses the unchanged Protocol Snapshot envelope. state holds the Core runtimeVersion 1.0.0, lifecycle, actionSequence, domain state and optional terminal result. Session revision equals the next action sequence. No source ID, event stream position, random generator, service, permission, DOM node or driver handle is copied. The new host uses its own source ID and contiguous local event stream; these are independent of restored domain revisions.

Persistence requires synchronous allowlist validators for domain state and portable driver data as well as the full envelope validator. They must reject credential fields, unsupported driver/state versions and proprietary objects. JSON copying rejects functions, accessors, cycles and custom instances; schemas alone cannot identify a secret stored as ordinary text. Keep credentials in host services, never domain state. All snapshots are copied/frozen with a 2 MiB limit.

restore validates schema, exact activity ID/type/schema/content digest, engine ID/state version, session/attempt identity, runtime state version, lifecycle/result consistency, action sequence and all drivers before committing. Failure returns a structured RuntimeError and leaves state, revision, action sequence and generation unchanged. Restore is synchronous, guarded against reentrancy and cancelable before commit. Event admission is preflighted before state replacement. It does not initialize live drivers during the transaction.

A successful restore changes the host-injected generation UUID before notifying subscribers. cancelEffects runs afterward as best-effort cleanup; old callbacks already fail correlation even if cancellation cannot stop the external service. Dispose the previous coordinator and create a fresh one bound to getEffectContext. Pending jobs and effect outboxes are never serialized or automatically reissued. Explicit retry is a new host decision with a new request ID; durable external submission idempotency belongs to the host.

Portable driver blobs remain quarantined JSON available through getDriverSnapshot and reserialization. Rehydrate them through host-approved effects before using driver services. The runtime does not silently execute an unsupported simulation driver or claim that a vendor snapshot is portable.

migrateSnapshot applies only explicitly selected, synchronous, bounded migration steps (at most eight). Each step declares its exact from/to snapshotSignature, including protocol/snapshot/activity/engine versions, content digest and driver version/encoding map. Input and every candidate must pass the supplied envelope validator; session/activity identity and revision are preserved. The final signature must equal the host target. Domain and driver validators run again in runtime.restore. No range-based or implicit upgrade occurs. Protocol wire migrations require a host validator that explicitly supports the source wire version; the current Protocol validator accepts 1.0.0 only.

Tests use quiz and flashcard fixture reducers to establish Core portability before those domain packages are implemented. They cover cross-host JSON round trips, sequence continuation, terminal state, corruption, content changes, missing/foreign attempts, migration failures, unsupported simulation driver state versions and callbacks arriving after restore. Snapshot storage/authorization is host-owned; no browser storage or remote upload is implicit.
